# 《吞噬星空》同人割草系统

文件已按三个角色整理。先进入对应目录，日常无需逐个查看全部文件。

| 目录 | 用途 | 常用入口 |
|---|---|---|
| [设定管理员](设定管理员/README.md) | 管理已确认设定、人物状态、大纲和前后矛盾 | [当前角色状态](设定管理员/state/character.md) |
| [系统设计师](系统设计师/README.md) | 管理技能、战力规则、积分经济和规则版本 | [技能池目录](系统设计师/docs/技能池目录.md) |
| [抽奖执行器](抽奖执行器/README.md) | 用程序随机抽取、记账、发放技能和保存日志 | [命令使用](抽奖执行器/命令使用.md) |

## 三个角色的边界

- 设定管理员维护已确认内容，发现矛盾先记录，不擅自改动核心规则。
- 系统设计师可以提出技能池、战力、融合或积分方案，所有新增或修改规则先交作者确认。当前已确认的品质与融合仍为关闭，不因目录分工而开启。
- 抽奖执行器按照已确认配置运行。候选由操作系统随机源生成，不由AI按剧情选择；扣款、升级、日志都由程序完成。角色最终状态只保存在一份正式存档中。

## 使用

在本项目根目录打开终端，Python 3.9+，macOS/Linux，无需安装依赖：

```sh
python3 抽奖执行器/system.py validate
python3 抽奖执行器/system.py status
```

发生实际剧情战斗后才记账。以下示例表示确实击杀10只初级兽将，然后付费抽金系池、选择第一项：

```sh
python3 抽奖执行器/system.py kill 初级兽将 10 --event 第一章-荒野战斗
python3 抽奖执行器/system.py draw metal
python3 抽奖执行器/system.py choose 1
```

新技能先入库，用`python3 抽奖执行器/system.py equip 实际技能ID`装备。初始3槽；完整规则仍以已确认配置和技能表为准。

检查脚本和数据：

```sh
python3 -m unittest discover -s 抽奖执行器/tests -v
```

本次仅整理文件归属和路径，技能、价格、五级效果、积分换算及已有角色状态均保持原样。
