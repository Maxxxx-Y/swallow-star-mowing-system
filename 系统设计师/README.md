# 系统设计师

负责技能池、战力层级、技能融合方案和积分经济的设计。所有新增或修改规则都先交作者确认，确认后再改正式配置。

## 本目录

- [技能池目录](docs/技能池目录.md)：26个池及全部固定五级效果。
- [抽取规则](docs/抽取规则.md)、[积分与配置](docs/积分与配置.md)、[数值规范](docs/数值规范.md)：当前已确认的规则。
- [新增技能指南](docs/新增技能指南.md)：新增技能和维护数据的方法。
- `data/`：技能、池归属、价格与系统配置的唯一权威定义。
- `schemas/`：JSON结构规范。
- `tools/`：初版制库和结构规范生成工具；`build_catalog.py`会覆盖数据，正常维护请直接编辑JSON。
- `versions/`：初版快照。历史文件和manifest保持原样，不能因新方案覆盖旧版本。

## 工作边界

现有技能品质和融合均为关闭。本角色可以设计未来融合方案，但目录整理和职责描述都不等于作者确认开启融合。角色积分与等级状态留在[设定管理员目录](../设定管理员/README.md)，程序抽取及日志执行留在[抽奖执行器目录](../抽奖执行器/README.md)。

修改前先处理待选抽取并备份；修改后从项目根目录执行：

```sh
python3 抽奖执行器/system.py validate
python3 抽奖执行器/system.py render
python3 -m unittest discover -s 抽奖执行器/tests -v
```

所有路径示例均相对于项目根目录。初版快照内部的相对路径仍按原版本结构解释。
