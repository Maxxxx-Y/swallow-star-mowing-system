# 新增技能指南

## 文件结构

```text
系统设计师/data/skills.json           技能唯一权威记录、归属和完整五级效果
系统设计师/data/skill_pools.json      26池分类、定位、原始积分价格
系统设计师/data/config.json          抽取、积分、上限、主线事件
系统设计师/schemas/                  JSON Schema，供编辑器提示与外部校验
抽奖执行器/system.py                 正式抽取器与校验器
设定管理员/state/character.json      正式角色状态与完整收支/抽取历史
设定管理员/state/character.md        从存档生成的中文角色面板
系统设计师/docs/技能池/              26份从JSON生成的中文技能表
抽奖执行器/reports/                  技能库校验与自动化测试结果
系统设计师/versions/1.0.0/           本次交付初版数据快照
抽奖执行器/tests/                    随机、跨池、收支及边界测试
系统设计师/tools/build_catalog.py    最初制库工具，正常加技能不要运行它
```

`系统设计师/tools/build_catalog.py`会重建原始初版的三份数据JSON，覆盖后续手动编辑。只用于主动恢复最初设计；用户日常加技能直接编辑JSON。

## 新增一项技能

1. 先完成待选抽取。复制`系统设计师/data/`与`设定管理员/state/`到自己命名的版本备份目录。
2. 在`skills.json`的`skills`数组中复制一条结构相近的记录。设置全新、永久稳定的ASCII ID，例如`metal_extra_001`；不要复用已有ID表示不同技能。
3. 写清名称、主功能（攻击/防御/控制/辅助）、机制及触发条件。在`pools`里列出所有归属，例如`["metal","blade"]`。跨池只加归属，绝不再复制整条技能。
4. 必须填完整Lv1–Lv5，各有独立文本及数字参数。每级列最终效果，不只写“比上级提升”。共享预算、使用资格、回收或控制限制应与《数值规范》一致。
5. 更新`catalog_version`和`config.system_version`，执行以下命令。

```sh
python3 抽奖执行器/system.py validate
python3 抽奖执行器/system.py render
python3 -m unittest discover -s 抽奖执行器/tests -v
```

`render`只重建技能目录、26池技能表和校验报告，不改正式存档，也不重新设计技能。角色状态用`status`更新。

## 注册新机制或成长参数

现有`mechanic`及数值键列在`抽奖执行器/system.py`中的`MECHANICS`、`CAPS`和`COUNTS`。普通新增技能复用既有机制即可，不需要修改Python。加入全新机制/参数时，同时更新这些注册表、`系统设计师/schemas/skills.schema.json`和数值说明，再补对应边界测试。初版每级使用一个核心成长参数，其余固定条件写进每一级的完整文本中。

JSON Schema可供支持JSON的编辑器使用；命令行内置校验器不依赖jsonschema第三方包，另检查跨记录引用和数值成长。它无法证明中文文本与数值的语义完全一致；编辑后仍需读一遍生成的中文技能表，尤其检查能量来源、叠加和条件例外。文本必须与`parameters`同义，不能把参数写5而文本写50%。

## 扩池与版本

现有26池ID保持不变。池成员仅由技能的`pools`推导，所以不会发生池里改成Lv3、另一处仍是Lv2的定义分叉。不要删除角色已拥有的ID；应继续保留旧定义，再用新ID新增不同技能。

已满级技能不会因扩池重置，新技能加入后自然重新出现候选。扩大池会稀释特定技能出现概率，必须在篇章/阶段开始前确定名单；每次抽取保存摘要以便追溯。不要在未结算的抽取中途改技能、价格或配置。

价格与奖励可编辑，改版不回算旧流水。涉及取消26池、改五级制、初始槽位、换算规则或上限体系时，属于结构规则升级，需要同步修改校验器；单纯增添现有池技能不需要。
